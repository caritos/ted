# ted

A small terminal text editor in Rust, for my own use. Goal: it just works, no configuration.

## Layout
- `src/buffer.rs` - rope-backed text + cursor + file load/atomic save + the undo/redo edit history (per buffer, capped at 10,000 steps, drives `is_modified`); records the lowest edited row (`take_dirty_row`) for the highlight cache. No terminal code.
- `src/editor.rs` - key handling, scrolling, status/message (plus a `[i/n]` tag and the line number setting, both set by the app; `scroll_col` and the cursor column are display columns, tabs expand to 4). `Editor::view()` returns a pure `View`; with line numbers on, its lines start with the gutter (`Style::LineNo`, hidden when fewer than 10 text columns would remain).
- `src/git.rs` - runs the `git` CLI (read-only) behind a `Git` trait: status, diff, log, baseline. No terminal code.
- `src/gitview.rs` - git view state machine: file list, selection by path, diff scroll, commit picker, refresh.
- `src/text.rs` - shared text helpers (width fitting, truncation, `sanitize`, and the editor tab layout `TAB_STOP` / `display_col` / `layout`) used by the views. Every string drawn (editor rows, status, message; git view; file tree) maps control chars to `?` one-for-one; in the editor that happens in `editor.rs`'s private `clip` (status, message, prompt) and `draw_cells` (text rows, built from `text::layout`); both sanitize every char, and together they are the only builders of `View` strings.
- `src/filetree.rs` - read-only file tree state (expansion, selection, refresh, rendering to rows). No terminal code.
- `src/bufferlist.rs` - buffer list state (selection, `ListAction`) and rendering to `Screen`. No terminal code.
- `src/help.rs` - help screen: static key table (`HELP`), scroll state (clamped at render), `HelpAction`, render to `Screen`. No terminal code. `App` has `Mode::Help` and `help_from`; F1 opens it everywhere, `?` from the three views.
- `src/app.rs` - owns the open buffers (`editors` + `current`, one `Editor` each), the optional git view, file tree and buffer list (`Mode` enum); Ctrl-G / Ctrl-T / Ctrl-O / `q` switch modes, Ctrl-N/P cycle buffers, Ctrl-W closes (`close_armed`), Ctrl-Q quits (`quit_armed`, counts every modified buffer). Opening a file adds or switches to a buffer. `App.search` is the one shared search term: pushed into the current editor before each key (`Editor::set_last_search`) and pulled back after it via `Editor::take_search`.
- Search / go to line: `Buffer::find`, `go_to_line`, `set_cursor` in `buffer.rs`; the Find / Go to prompt lives in `editor.rs` (`in_prompt`, `cancel_prompt`); `app.rs` routes every key to an open prompt first (only Ctrl-Q escapes it); the remembered term is shared by all buffers through `App.search`.
- Replace / match highlight: `Buffer::matches_in_line` and `replace_all` (one undo `Edit`) in `buffer.rs`; in `editor.rs` the two-step `PromptKind::Replace` (`Replace:` then `With:`, `open_replace`, Ctrl-R / `replace` command) and `mark_matches` (`Style::Match`, underline in `main.rs`, visible rows only, only while a Find prompt has a term; drawn before the selection so `Selected` wins and the match replaces the syntax colour on its cells). Tests in `src/editor/replace_tests.rs`, `src/app/tests/replace.rs`.
- `src/command.rs` - command prompt logic (`NAMES`, `Command`, `matches`, `complete`, `parse`; `TAKES_ARGUMENT` decides which names Tab follows with a space). No terminal or editor state. The Ctrl-X prompt is `PromptKind::Command` in `editor.rs` (`take_command` hands the accepted text to `App::finish_key` -> `App::run_command`); `saveas` is `Buffer::save_as` + `Editor::save_as` + `App::save_as` (never overwrites, refuses a file open in another buffer).
- `src/fuzzy.rs` - `score` / `rank`: subsequence match of a query against paths (case-insensitive; file-name matches, consecutive chars and word starts score higher, shorter paths win ties). Pure.
- `src/finder.rs` - the open-file-by-name view (`Finder`: query, ranked list, selection, `FinderAction`, render to `Screen`) and `walk_files` (the no-git fallback). No terminal code. `App` has `Mode::Finder`, `enter_finder` (Ctrl-E / `open` command; file list from `Git::files`, else `walk_files`), and routes bracketed paste to it.
- `src/screen.rs` - plain `Screen` value (rows of styled spans) that both modes render to; `Style` includes the syntax styles.
- `src/highlight.rs` - Rust tokenizer (std only, char-based), chosen by file extension; `Editor::view` fills per-char styles from it, caching the `LineState` at the start of each line (cut back at the buffer's dirty row, per `Editor`, reset on a language change).
- Selection model: `Buffer` holds an anchor (char index; the cursor is the other end) with `selection`, `selected_text`, `select_all`, `clear_selection`, `delete_selection`, `insert_str` (paste and any multi-char input go through it, one rope insert and one undo step; never per-char `insert_char`), the `move_*_select` moves, and `selection_anchor` / `restore_selection` (a prompt remembers the anchor and puts it back on Esc). `Editor` maps Shift+move and Ctrl-A, draws `Style::Selected` over the syntax styles (`mark_selection`), and has thin wrappers for the app (`selected_text`, `cut_selection`, `insert_text`, `select_all`, `paste_into_prompt`).
- `src/clipboard.rs` - `Clipboard` trait (`get`/`set`), `SystemClipboard<R: Runner>` (pbcopy/pbpaste, wl-copy/wl-paste, xclip; every call within a 2 s `TIMEOUT`; missing tool, non-zero exit, non-UTF-8 and timeout = unavailable), `ProcessRunner` (the real runner, with reader/writer threads and a kill at the deadline), `MemoryClipboard` (tests; clones share state). `App` owns a `Box<dyn Clipboard>` (`App::with_clipboard` for tests) plus an in-memory register that copy and cut always fill and paste falls back to. Ctrl-C / Ctrl-K / Ctrl-V and `copy` / `cut` / `paste` / `selectall` live in `app.rs`; `App::paste(&str)` is the bracketed paste entry (editor: one undo step; prompt: line breaks removed, Goto digits only, capped at 4096 chars; views and help ignore it).
- `src/main.rs` - thin crossterm layer only: raw mode, bracketed paste on/off (also in `restore()`, so the panic hook disables it), read keys and `Event::Paste`, draw the `View` (`Style::Selected` = reverse video). Keep logic out of it.
- `scripts/pty_smoke.py` - drives the release binary through a pty.

## Commands
- Fast tier: `cargo test`
- Lint: `cargo clippy --all-targets`
- Real-terminal check: `cargo build --release && python3 -I scripts/pty_smoke.py target/release/ted`
- Run: `cargo run -- <file>`; install: `cargo install --path .`
- Rust comes from rustup via Homebrew; if `cargo` is missing, `export PATH="/opt/homebrew/opt/rustup/bin:$PATH"`.

## Rules
- TDD: failing test first. Logic goes in the library (`buffer`, `bufferlist`, `editor`, `git`, `gitview`, `help`, `filetree`, `text`, `app`, `screen`, `highlight`, `command`, `clipboard`) so it is testable without a terminal.
- A missing file opens as an empty buffer; any other read error (incl. non-UTF-8) is an error. Never overwrite on a failed read.
