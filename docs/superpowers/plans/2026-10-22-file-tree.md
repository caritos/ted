# File Tree View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ctrl-T opens a full-screen, read-only, vim-netrw/NERDTree-style file tree of the directory `ted` was started in: nested, collapsible directories, Up/Down to move, Enter to open a file in the editor.

**Architecture:** A new `FileTree` state machine in the library (lists directories lazily, keeps expansion and selection by path, renders to the existing `Screen`) becomes a third mode in `App` next to the editor and the git view. Text clipping/sanitizing helpers move out of `gitview.rs` into a shared module so both views use one implementation. `main.rs` only gains one style mapping.

**Tech Stack:** Rust 2024, crossterm 0.29, std only. No new dependencies.

**Spec:** none written; the user opted out of the brainstorming questions and asked for: "a regular file view, much like nested in vim, so I can see the whole directory of files". The design decisions below (key, layout, behavior) are the controller's calls and are listed in "Decisions" for the user to review.

## Decisions (controller's calls)
- Key: **Ctrl-T** toggles the file tree (like Ctrl-G for the git view). Ctrl-G inside the tree jumps to the git view; Ctrl-T inside the git view jumps to the tree.
- Full-screen single pane (not a sidebar next to the editor).
- Rooted at the `App` location (the directory `ted` was started in, or the parent of the file given). Never goes above the root.
- Shows everything including dotfiles, except the `.git` entry. Directories first, then files; names sorted by trimmed, case-insensitive key with the exact name as tie-break.
- Read-only: it never creates, renames or deletes anything.
- Directories expand lazily; expansion state and selection survive refreshes and leaving/re-entering the tree within a session.
- Refreshes about once a second while showing (re-reads only expanded directories), so new files from Claude appear.
- Enter on a file opens it in the editor, with the same guards as the git view (refused if the buffer has unsaved changes; refused with "File no longer exists" if it vanished).

## Global Constraints
- TDD: failing test first; logic in the library crate, `main.rs` thin. `cargo test` and `cargo clippy --all-targets` clean; no new dependencies.
- Real-terminal check: `cargo build --release && python3 -I scripts/pty_smoke.py target/release/ted` must pass. If `cargo` is missing: `export PATH="/opt/homebrew/opt/rustup/bin:$PATH"`.
- Never call the real clock in library code. Tests use real temp directories (unique names under `std::env::temp_dir()`, cleaned up on drop), never the user's files.
- A failed directory read is shown (message and a dim `(cannot read)` row), never as an empty directory that looks real.
- All file-name text is sanitized (C0/C1 controls and DEL to `?`) and clipped by chars; no row, status or message exceeds the width and the screen never exceeds the height, for every size from 0x0 upward.
- Existing behavior is unchanged: editor keys, quit rules (Ctrl-Q rules in every mode), git view behavior, `ted <file>`/`ted <dir>`.
- Update `README.md` and the dated log and layout in `CLAUDE.md`; claim nothing as hand-verified.

## Review Focus
1. File names with spaces, unicode, newlines and escape characters (Task 2 renders them safely; Task 1 keeps paths exact).
2. Symlinks: to a directory (shown as a directory, expandable once; a cycle must not hang because expansion is lazy), broken symlink (shown as a file; opening it is refused by the App's existence check).
3. A directory that disappears or becomes unreadable while expanded or selected (Task 1).
4. Collapsing a directory that contains the selection (selection moves to that directory) (Task 1).
5. Tiny terminals and a very large directory (Tasks 2, 3).

## File Structure
- `src/text.rs` (create): shared `sanitize`, `clip`, `pad`, `styled`, `window_start` moved verbatim out of `src/gitview.rs` (`pub(crate)`); no behavior change. Existing tests keep passing.
- `src/filetree.rs` (create) + `src/filetree/tests.rs`: `FileTree` state machine and rendering.
- `src/screen.rs` (modify): add `Style::Dir`.
- `src/app.rs` (modify) + `src/app/tests.rs`: `Mode` enum, Ctrl-T, mode switching, tick refresh.
- `src/main.rs` (modify): draw `Style::Dir` (bold blue).
- `src/lib.rs` (modify): `pub mod text; pub mod filetree;`.
- `scripts/pty_smoke.py`, `README.md`, `CLAUDE.md` (modify).

### Task 1: Shared text helpers and `FileTree` state

**Files:**
- Create: `src/text.rs`, `src/filetree.rs`, `src/filetree/tests.rs`
- Modify: `src/gitview.rs` (use the shared helpers; delete the moved private fns), `src/lib.rs`

**Interfaces:**
- Produces in `ted::text` (`pub(crate)`): `fn sanitize(s: &str) -> String`, `fn clip(s: &str, n: usize) -> String`, `fn pad(s: &str, n: usize) -> String`, `fn styled(s: &str, width: usize, style: Style) -> Row`, `fn window_start(selected: usize, height: usize) -> usize` — same signatures and behavior as the current private versions in `gitview.rs`; this is a pure move, all existing tests must still pass unchanged.
- Produces in `ted::filetree`:
  - `enum TreeAction { None, Back, ToggleGit, Open(String) }` (`Debug, PartialEq, Eq`); `Open` carries a root-relative path with `/` separators.
  - `struct FileTree` with `pub fn new(root: PathBuf) -> Self` (root listed and expanded immediately), `pub fn refresh(&mut self)`, `pub fn handle_key(&mut self, key: KeyEvent) -> TreeAction`, `pub fn selected_path(&self) -> Option<&str>`, `pub fn message(&self) -> &str`, `pub fn set_message(&mut self, String)`, and `pub(crate) fn visible(&self) -> Vec<VisibleRow>` for tests and rendering, where `VisibleRow { pub depth: usize, pub name: String, pub path: String, pub kind: NodeKind, pub expanded: bool, pub unreadable: bool }` and `enum NodeKind { Dir, File }`.
  - Listing rules: entries of a directory are read with `std::fs::read_dir`; the `.git` entry (file or directory) is skipped; an entry is a `Dir` if `std::fs::metadata` (following symlinks) says directory, otherwise `File` (including broken symlinks); order is directories first, then files, each sorted by the trimmed, case-insensitive name with the exact name as tie-break; names are lossy UTF-8. Directories are read lazily when expanded. A directory that cannot be read gets `unreadable = true` (shown as a single child row `(cannot read)` later in Task 2) and sets `message` to `"Cannot read {name}: {error}"`.
  - Keys (plain, no Ctrl/Alt unless stated): Up/Down move the selection and clamp at the ends; PageUp/PageDown move 10 rows; Home/End jump to the first/last row; Right expands a collapsed directory, or moves to its first child if already expanded (nothing on files); Left collapses an expanded directory, otherwise selects the parent (nothing at depth 0); Enter toggles a directory or returns `Open(path)` for a file; `q`/Esc/Ctrl-T return `Back`; Ctrl-G returns `ToggleGit`; everything else does nothing.
  - Selection is stored as a path, never a row index. If the selected path disappears on refresh, select its nearest surviving ancestor; if the root itself cannot be read, `visible()` has the single unreadable root marker and nothing is selectable. Collapsing a directory that contains the selection selects that directory. Expansion state is keyed by path and dropped when the directory disappears.

### Task 2: Render the tree

**Files:**
- Modify: `src/filetree.rs`, `src/filetree/tests.rs`, `src/screen.rs` (add `Style::Dir`), `src/main.rs` (draw `Style::Dir` as bold blue; reset attributes after the span as for the other styles)

**Interfaces:**
- Consumes: Task 1.
- Produces: `FileTree::render(&self, width: usize, height: usize) -> Screen`. `height` includes the status row and the message row (like `GitView::render`).
  - Body rows: two spaces of indent per depth, then a marker (`v ` expanded directory, `> ` collapsed directory, two spaces for a file), then the name, with a trailing `/` on directories. An unreadable directory shows one child row `(cannot read)` styled `Dim`. Directory rows are styled `Dir`; the selected row is `Selected` and padded to the full width; files are `Normal`. The visible window keeps the selection in view (`text::window_start`). All text goes through `text::sanitize`/`clip`/`pad`.
  - Status row (padded to exactly `width`): `Files: {root directory name}  {N} entries visible`; an empty root shows `Files: {root name}  (empty)`; an unreadable root shows `Files: {root name}  Error`. Message row: `message()`. `cursor` is `None`.

### Task 3: `App` mode switching

**Files:**
- Modify: `src/app.rs`, `src/app/tests.rs`

**Interfaces:**
- Consumes: `FileTree`, `TreeAction`, existing `App` open logic (`App::open(&str)` with its unsaved-changes and missing-file guards).
- Produces: `App` gains a private `enum Mode { Editor, GitView, Files }` replacing the `in_git_view: bool` field; keeps `pub fn in_git_view(&self) -> bool` and adds `pub fn in_file_tree(&self) -> bool`. `FileTree` is created on the first Ctrl-T with root = the app location and kept afterwards.
  - Ctrl-T in the editor enters the tree; Ctrl-T in the tree or `q`/Esc returns to the editor exactly as before (buffer and cursor untouched); Ctrl-T in the git view switches to the tree; Ctrl-G in the tree switches to the git view (creating/refreshing it as Ctrl-G does today). Entering the tree calls `refresh()`. Entering either view from the editor cancels a pending quit warning, as Ctrl-G does today.
  - `TreeAction::Open(rel)` goes through the same `App::open` as the git view; on success the app returns to the editor. Its refusal messages ("Unsaved changes: save or quit first", "File no longer exists", "Open failed: {e}") must appear in the tree's message row (`FileTree::set_message`) while staying in the tree.
  - Ctrl-Q in the tree follows the editor's quit rules exactly as in the git view. `tick` refreshes the tree while it is showing (and the git view while it is showing, as today), and does nothing in the editor. `screen()` renders the tree in Files mode.
