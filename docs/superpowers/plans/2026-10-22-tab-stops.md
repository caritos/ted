# Tab Stops Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tab character in a file is drawn as spaces up to the next tab stop (every 4 columns) in the editor, so columns line up; the cursor, horizontal scroll and syntax styles stay aligned.

**Architecture:** Display columns differ from char columns once tabs exist. A pure helper in `text.rs` maps display columns to source chars; `Editor::view` uses it for row text, styles, cursor column and horizontal scrolling. The buffer, cursor positions (char columns), saved bytes and the status `row:col` stay char-based.

**Tech Stack:** Rust, existing crates only.

**Spec:** none; design calls below (user may veto). Closes the "tab-stop expansion" item of issue #3.

## Design calls

- Tab stop is 4 (`text::TAB_STOP`), matching the Tab key, which still inserts spaces (`TAB_WIDTH` in `editor.rs` becomes the same constant or is replaced by it).
- A tab at display column `c` draws `TAB_STOP - c % TAB_STOP` spaces (1..=4), in the style of the tab char.
- The cursor on a tab sits at the tab's first cell; the cursor after it sits at the next stop.
- Horizontal scrolling counts display columns; a tab cut by the left edge shows only its remaining cells.
- Status bar `row:col` stays the char column. Up/Down keep the char-based goal column, so a line with tabs may shift the cursor visually; accepted.
- Editor rows only. The git diff, tree, status, message and prompt keep one space per tab (deferred).
- Wide chars (CJK/emoji) stay out of scope.

## Review Focus

- A tab in the middle of text, at column 0, several in a row, and a line of only tabs.
- A tab straddling the left scroll edge or the right edge (clipped, no panic).
- Cursor before/on/after a tab; typing a char right after a tab; End on a line ending in a tab.
- Highlighting on a `.rs` line with tabs (indent before `fn`, tab inside a comment or string): styles line up with the drawn cells.
- Gutter on and off with tabs; tiny sizes 0..=16 x 0..=6 with tab lines: no panic.

### Task 1: Tab expansion in the editor view

**Files:**
- Modify: `src/text.rs` (helpers + unit tests in its test module), `src/editor.rs` (`view`, `styles`, `clip` use, `TAB_WIDTH`), tests in `src/editor/tab_tests.rs` (new; add `#[cfg(test)] mod tab_tests;` next to the other test modules), `scripts/pty_smoke.py`, `README.md`, `CLAUDE.md` (layout line for `text.rs`/`editor.rs`, dated log entry: done / not hand-verified / deferred).

**Interfaces:**
- Produces in `src/text.rs`:
  - `pub const TAB_STOP: usize = 4;`
  - `pub fn display_col(line: &str, char_col: usize) -> usize` — display column where char index `char_col` starts (tabs advance to the next stop; every other char is 1; `char_col` past the end counts the whole line then 1 per missing char).
  - `pub fn layout(line: &str, skip: usize, width: usize) -> Vec<usize>` — for display columns `skip..skip+width` (stopping at the end of the line) the source char index of each cell; a tab yields its own index once per cell it covers. Must not walk past the last needed column (long lines stay cheap).
- `Editor::view` builds each text row from `layout` (cell char = source char via `sanitize_char`, but a tab cell is `' '`; cell style = style of the source char's token), computes the cursor column and `scroll_col` from `display_col`, and keeps the gutter logic unchanged. `Editor.scroll_col` is now a display column.
