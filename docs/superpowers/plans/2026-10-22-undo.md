# Undo / Redo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ctrl-Z undoes and Ctrl-Y redoes edits in the current buffer, per buffer, with typing runs undone in one step, and the `[+]` marker and quit warnings reflect whether the text really differs from the saved file.

**Architecture:** `Buffer` records every edit (the four primitives: insert char, insert newline, backspace, delete) as one `Edit { index, removed, inserted, before, after }` on an undo stack, merging adjacent typing. Undo/redo apply an edit in reverse/forward through the same rope operations, re-place the cursor from a char index (`place_cursor`) and mark the dirty row for the highlight cache. The modified flag becomes "history position differs from the position at the last save". `Editor` maps keys and gives messages; `command.rs` gets `undo` and `redo`.

**Tech Stack:** Rust, existing crates only.

**Spec:** none; design calls below (user may veto).

## Design calls

- Keys: Ctrl-Z undo, Ctrl-Y redo (editor mode, not while a prompt is open; raw mode delivers Ctrl-Z as a key). Commands `undo` and `redo` (`NAMES` grows; `u`-style unique prefixes work as for the others). Messages when empty: `Nothing to undo` / `Nothing to redo`; otherwise no message.
- History is per buffer, lives as long as the buffer, and is lost when an unmodified buffer is reloaded from disk (the existing reopen behaviour). Saving and `saveas` keep it.
- One step = one `Edit`. Merging: a typed non-newline char merges into the previous edit when that edit is an insert-only edit of non-newline chars ending exactly at the cursor; Backspace of a non-newline char merges into a previous removal-only edit that starts right after it; Delete of a non-newline char merges into a previous removal-only edit at the same index. Newlines (typed, or removed by Backspace/Delete) are always their own step. Merging is also off right after a save, an undo or a redo (`merge_ok` flag), and when the cursor is not where the previous edit left it.
- A new edit clears the redo stack. The undo stack is capped at 10,000 edits (oldest dropped).
- Cursor: undo puts the cursor at the edit's `before` char index, redo at its `after` index.
- Modified flag: `modified = (history position != clean position)`. The clean position is the undo-stack length at the last open/save/saveas (a new or opened buffer starts clean at 0), becomes unreachable (`None`) when a new edit cuts the redo branch that contained it or when the cap drops it. Typing then undoing everything is unmodified again; undo past a save is modified; redo back to the saved state is unmodified.
- Out of scope: undoing cursor-only moves, selections, a history tree, grouping by time, persistent undo.

## Review Focus

- Undo/redo around line joins and splits, including lone `\r` and `\r\n` text: the text round-trips and the cursor is valid (no panic) after every step.
- Randomized sequences of insert/newline/backspace/delete/moves/undo/redo/save: undoing everything restores the original text, redoing everything restores the final text, the dirty-row highlight cache agrees with a from-scratch walk, and `is_modified` matches "text differs from the last saved text" except where the clean position is unreachable.
- Save, undo, redo, then quit: the Ctrl-Q warning appears exactly when the text differs from disk.
- Undo on an empty history, redo with nothing undone, undo at a read-only/unnamed buffer: messages, no panic.
- Typing after an undo does not merge into the older edit and clears redo.
